### 0.2 路径记法与唯一落位规则

本文后续统一使用以下缩写，防止混淆 `repo/artifacts/` 与根目录的 `artifacts/`。

| 记号 | 实际位置 | 存放对象 |
| --- | --- | --- |
| `R/` | `WORK_ROOT/repo/` | 代码、说明、配置模板、锁文件、小型可公开夹具 |
| `D/` | `WORK_ROOT/data/` | 原文、快照、索引、数据库、任务、训练数据 |
| `M/` | `WORK_ROOT/models/` | 下载的冻结模型与 tokenizer |
| `A/` | `WORK_ROOT/artifacts/` | 检查点、适配器、导出包、报告、发布包 |
| `L/` | `WORK_ROOT/runs/` | 实际运行、费用、审核、验收与故障记录 |
| `E/` | `WORK_ROOT/envs/` | 四套环境和安装缓存 |

后续只允许在已登记的目录或其 ID 子目录中新增文件。目录树中的模块目录已允许容纳职责相符的源文件，但新增公共协议、配置入口或文档类别，必须先更新 `R/docs/plan/directory_registry.md`。不得新建同义平行目录，例如再建 `results/`、`output/`、`new_data/`、`final_final/`。

1. **代码与大文件分离。** Git 仓库不保存环境、完整模型、用户资料、正式原始实验结果和真实密钥；公开的小样本需单独核验。`R/artifacts/artifact_index.json` 只记录实际大文件的位置、哈希和用途。
2. **名称固定。** `Rule` 保留大写 R；其他目录使用小写英文与下划线；中文用于文档正文与界面。原始上传名保留为显示字段，磁盘文件使用系统 ID。
3. **ID 不随意命名。** 步骤为 `S01`—`S50`，尝试为 `a001`、`a002`；其余 ID 使用“类型前缀＋固定宽度序号”，例如 `exp_sft_0001`、`eval_main_0001`。跨机器合并前检查唯一性。真实时间写入元数据，时间不是执行顺序依据。
4. **每一步有记录。** 统一写入 `L/steps/<step_id>/<attempt_id>/`，文件模板固定为 `acceptance.md`、`evidence_index.json`、`failure.md`。通过也要写明检查范围，失败不能仅口头说明。
5. **数据和结果不覆盖。** 新数据用新 dataset_id，新实验用新 experiment_id；正式失败结果保留。活动模型、索引可以更新“当前版本指针”，历史运行始终引用原版本。
6. **配置不散落。** 业务参数在 `R/configs/project.yaml`，路径在 `paths.yaml`，真实密钥在 `L/system/private.env`。模块不能各自硬编码一份预算、数据规模或模型名。
7. **目录调整先登记。** 确有必要时，在 decision_log 中说明原路径、新路径、原因、影响和迁移验证；更新目录树、配置与引用后再迁移。不能边开发边随手换名字。
8. **原方案可追溯。** 原说明归档为 `R/docs/source/project_spec_v1.0.md`，本方案放 `R/docs/plan/execution_plan.md`；后续更正放决策日志，不直接改写归档来掩盖差异。
9. **缓存和备份受空间约束。** 原方案 100GiB 控制值保持为：repo 2、envs 35、models 20、data 15、artifacts 10、runs 8、余量 10。备份暂存属于 runs，不能无限累积；若模型或依赖实际超出配额，先核算总空间，再按预算规则处理，不删除唯一产物。
10. **电脑备份镜像结构。** 备份包按同一相对路径组织，并附 SHA-256 清单。服务器不是唯一保存位置；恢复时不得凭文件名猜版本。

## 1. 使用方式、依据与统一判断规则

### 1.1 本方案的任务边界

依据：用户上传的《EvidenceAgent 项目说明与执行手册》1.0，核验日期为 2026-10-25。本文将原方案按依赖重新组织，不按周、不按天排期。超时、资源配额、费用上限属于系统约束，仍然保留。

默认项目从零开始。已经完成的工作可直接提交验收证据，验收通过后跳过重复建设。本方案是未来执行手册，不代表已经租机、训练或取得性能提升。

项目仍为：面向文档与网页的可追溯证据研究助手；单个顺序研究控制器；固定 Writer、Verifier；Qwen3-4B 决策模型；QLoRA SFT 与一次合格规模 DPO 实验；单张 RTX 4090 24GB；FastAPI、Streamlit、SQLite、混合检索；总预算不超过 1,500 元。

不增加 OCR、任意代码执行、多用户权限、在线 RL、多卡、GraphRAG 或其他原说明排除的功能。最终应有可操作应用，而非仅有论文调研与训练曲线。

### 1.2 三类要求必须分开记录

| 标记 | 含义 | 如何处理 |
| --- | --- | --- |
| 原定要求 | 原说明已有的选型、参数、门槛与边界 | 默认照办；修改必须记录影响并重验 |
| 执行补充 | 本文为消除歧义新增的步骤、检查方法与流程口径 | 在正式采数或训练前冻结，不能事后迎合结果 |
| 运行时确认 | 价格、账号权限、实例地址、revision、显存与真实效果 | 通过实际查询或探针填写；禁止预造 |

原说明正文与附录 A 配置冲突时阻断相关流程，先统一配置和文档。本文补充不得悄悄改写原定科学目标或把未完成项删掉。

### 1.3 每一步的统一验收流程

所有 S 步骤都执行：检查前置证据 → 按顺序执行 → 保存产物 → 执行验收 → 写通过或失败记录 → 更新 progress → 决定去向。记录至少包含：输入版本、代码提交、配置哈希、检查项、实际结果、产物位置、失败原因和依赖影响。

- **通过 PASS：** 本步骤全部必需检查通过，证据可打开、产物可定位，才可放行依赖步骤。
- **返工 REWORK：** 发现可修复的实现或数据问题，退回指定步骤；受影响的衍生产物标为失效，不能混用。
- **阻断 BLOCKED：** 硬件、权限、数据最低规模等前置条件不满足；停止依赖它的长任务，其他独立工作可以继续。
- **降级 DEGRADED：** 触发原定回退，例如发布 E0；保留可用成果，同时清楚标记完整项目中仍缺少的训练或评测。
- **停止 STOPPED：** 费用或资源上限触发，不再派发新付费工作；保存账本与可恢复位置。

“损失下降”“网页能打开”“教师说正确”都不能单独作为项目验收通过。输出真实、可追溯和条件一致比凑齐漂亮结果更重要。

### 1.4 已补充明确的歧义

1. 环境检查拆成基础探针与产品验收，尚未开发的上传、恢复功能不作为安装环境的先决条件。
2. 每个训练／开发任务最多两条教师候选轨迹；两条均失败时最多增加一条本地基座补救轨迹，总尝试上限三条。教师整体不可用时最多两条本地候选，仍失败不继续追加。此为第 15.1 节的执行补充，需在采集前登记。
3. SFT 检查点先在固定 40 个开发任务上筛选，再在完整 160 个开发任务上确认候选。最终 E0/E1/E2 发布选择使用相同的完整开发集，不能混用子集结果。
4. DPO 依赖一个格式、权限、预算和导出均正常的 SFT 策略。SFT 训练流程失败时阻断 DPO；SFT 可执行但没有通过发布效果门槛时，可以作为研究参考继续 DPO，但不能提前把 E1 当作已发布模型。
5. 同时保留“产品可用”“训练实验完成”“完整评测完成”三种状态。E0 可用不等于 SFT/DPO 已完成；DPO 不适合发布不等于 DPO 实验未完成。
6. 部分检索和功能环节无原定总体准确率阈值，本文采用明确夹具和预先登记检查项，不凭空要求一个百分数。新增统计门槛必须明确标为补充并在正式运行前冻结。
7. 引用支持率无定义时，不把它设成 100%。开发集候选若没有足够可判引用任务，则支持性门槛未被证明，不据此发布训练版；DPO 分支无可比 G 时，不使用“同质但便宜”规则造偏好。

4. 明确“动作执行前登记—结果事务提交—下一步推进”的持久边界；大型原文和模型不放 BLOB。
5. 幂等 key 绑定请求体哈希：同 key 同体取原 run，同 key 不同体报冲突。用固定夹具验证，不靠真实付费请求反复试。

**产出位置：** `R/docs/architecture/{api_contract,storage_design}.md`、`R/src/evidence_agent/{api,storage}/`、`D/app/`、`R/tests/contract/`。

**不通过与去向：** 发现任务重复、跨项目读取或半条结果即停止依赖任务，修 S09 后重验。数据库变更必须有迁移与回退记录，不直接删除历史运行掩盖问题。

### S10｜实现上传校验与文件解析

**依据与细节重述：** 原说明第 5、9.1、23 节。只支持 PDF/MD/TXT；单文件≤20MiB、PDF≤200页、项目≤50文档；TXT/MD 仅 UTF-8 或 BOM；文字 PDF 优先 pypdf，表格辅以 pdfplumber；不做 OCR。

**前置：** S09 文档、版本和任务存储契约通过。

**执行：**

1. 先校验后缀、MIME、签名、大小和数量；对空文件、伪装格式、非法编码、不能提取的加密 PDF 返回可辨错误。
2. 原文件按生成 ID 保存，保存 SHA-256；不把用户输入的文件名当磁盘路径。
3. PDF 提取后计算平均每页非空白字符，少于30标 needs_ocr，不继续把空内容送去索引；个别空白页另记局部问题。
4. 保留段落、标题、页码和表格结构；跨页表格不能可靠合并就标可能不完整，不生成肯定的完整表格事实。
5. 页面显示上传、校验、解析、索引各状态，解析失败不能显示“资料已就绪”。

**产出位置：** `R/src/evidence_agent/ingestion/`、`D/raw/`、`D/normalized/`、`R/tests/fixtures/`、`L/inference/`。

**通过与下一步：** 合法边界接受，超限拒绝；扫描件、非法编码有明确状态，原文件哈希可核对；进入 S11。

**不通过与去向：** 对应文件留在解析失败状态，修校验或解析；不要靠删掉难例通过验收。若来源本身不受支持，准确拒绝，不能在本项目临时增加 OCR。

### S11｜建立原文位置映射、去重与版本快照

**依据与细节重述：** 原说明第 9.1—9.2、11、23 节。MD/TXT 保存标题、行号与 Unicode 码点左闭右开区间；PDF 保存页码与页内字符偏移，不声称是视觉坐标。更新文档创建新版本，旧运行继续引用旧快照。

**前置：** S10 提取文本可用。

**执行：**

1. 将清洗前、清洗后文本和映射分别保存，明确 BOM、换行、空白处理对偏移的影响。
2. 准备中文、英文、emoji、全角符号、标题、表格夹具；从片段位置反查原文再做逐字比较。
3. 同内容改名上传按内容去重，仍保留用户显示名与来源关系，不制造内容版本冲突。
4. 同一文档更新时创建新 source_version_id，索引引用版本集合；已有 run 锁定原集合。
5. 用“先运行—更新文件—再打开旧 run”验证旧引用仍可还原，不能只检查新文件的位置。

**产出位置：** `D/normalized/`、`D/manifests/`、`R/src/evidence_agent/{ingestion,storage}/`、`R/tests/boundary/`。

**通过与下一步：** 夹具所有引用区间与原文一致；更新不改旧证据；进入 S12。

**不通过与去向：** 偏移或版本错误阻断证据台账和训练。修复后重新生成受影响解析、分块和索引；涉及历史运行时保留旧解析版本并标错误，不静默重写旧结论。

### S12｜分块并构建版本化索引

**依据与细节重述：** 原说明第 9.2—9.3 节和附录 A。chunk 同时满足 Qwen≤384 Token、embedding≤512 Token；相邻重叠≤64 Qwen Token；保留 parent_section_id；bge-m3 仅 dense，归一化＋FAISS IndexFlatIP，BM25 中文 jieba、英文正则分词。

**前置：** S11 位置与版本通过；S07 embedding 探针通过。

**执行：**

1. 按标题、段落和 PDF 页边界切分，再用两套 tokenizer 检查；超过任一限制继续切。
2. 代码块、表格不得无提示截断，必须切开时带标题、片段说明和原文位置；保存父章节关系。
3. 用固定模型 revision 生成 dense 向量，检查维度、有限值与归一化；索引批量16、CPU线程上限8。
4. 建 BM25；索引绑定来源版本集合、分块器、模型 revision 与配置哈希。新索引写完后原子替换当前指针。
5. 完成后校验资料数量、块数量、索引数量和可检索状态，禁止空索引被标为成功。

**产出位置：** `D/chunks/`、`D/indexes/`、`D/manifests/`、`R/src/evidence_agent/{ingestion,retrieval}/`。

**通过与下一步：** 所有块符合双长度限制、位置不丢、索引版本和块一一对应；进入 S13。

**不通过与去向：** 分块丢条件回 S11/S12；维度和模型问题回 S06/S07。调整分块会使旧检索结果、轨迹和训练数据失效，必须换数据版本重新构建。

### S13｜接通固定混合检索流水线

**依据与细节重述：** 原说明第 9.3 节。BM25前20＋dense前20；按 source_version_id+chunk_id 去重；RRF常数60、rank从1开始；融合前12重排，返回前6；预览每条≤72 Qwen Token；预览不能作为已读证据。

**前置：** S12 索引通过，CPU reranker 可用。

**执行：**

1. 每条查询保存两路候选、融合顺序、重排顺序与最后候选，便于区分召回失败和重排失败。
2. 用实体名、版本号、中文问句、英文 API 名称、多文档问题做固定功能夹具；在运行前写下预期原文位置。
3. 返回 candidate_id、标题、位置、版本、短预览与来源，不把完整历史挤进控制器。
4. 缓存键绑定项目版本集合与查询；记录冷／热缓存，不能混淆缓存命中和外部费用。
5. 对零结果给空候选和明确状态，不捏造 chunk 或降低权限范围寻找答案。

**产出位置：** `R/src/evidence_agent/retrieval/`、`L/probes/`、`R/tests/fixtures/`、`R/docs/plan/acceptance_registry.md`。

**通过与下一步：** 算法顺序与配置一致，固定夹具期望位置能进入预登记候选范围，候选真实存在；进入 S14。此处没有原定通用 Recall 百分数，不事后发明分数。

**不通过与去向：** 根据记录定位到分词、召回、融合或重排，回 S12/S13；若夹具本身没有答案，修夹具并留版本，不能把错误期望硬算作系统成功。

### S14｜实现网页发现、正文快照与三种模式

**依据与细节重述：** 原说明第 5、9、11、13、15.4 节。off 不联网；replay 从冻结网页库搜索；live 使用 Tavily basic，每次最多5候选、每任务最多3次真实搜索。摘要和正文必须区分。

**前置：** S11 来源版本机制、S13 检索器可用；真实搜索还需 S04 额度与权限。

**执行：**

1. 网页发现只登记候选 URL、标题、摘要；用户文件问答默认 off，开启后才允许 live 搜索。
2. 读取时使用 HTTPX＋Trafilatura 留存正文、canonical URL、抓取时间、内容哈希与来源状态。
3. 登录墙、动态页提取失败、空正文、仅摘要有答案都不能升级为已读证据。
4. replay 接入冻结来源库和同一检索器，返回前5；明确它不是重现任意查询当年的搜索引擎排名。
5. 用户资料不随搜索上传；只发送确有必要且允许公开的查询词。创建三模式的功能夹具和用量记录。

**产出位置：** `R/src/evidence_agent/tools/`、`D/snapshots/`、`D/manifests/`、`L/probes/`。

**通过与下一步：** off 无外部调用、replay 可重复、live 发现与阅读分开，失败不会生成证据；进入 S15。

**不通过与去向：** live 不可用可保留 off/replay，但 live 项标为未通过；提取与快照错误回 S11/S14。不得用 Tavily 摘要替代正文来凑验收。

### S15｜统一工具契约、读取权限与失败规则

**依据与细节重述：** 原说明第 10、13.2、23 节。外部工具只有 local_search、web_search、read_evidence；读取只接受已登记 candidate_id；HTTP/HTTPS，单次≤5MiB，重定向≤3，读取15秒、搜索20秒，暂时错误最多重试一次。

**前置：** S13/S14 基础能力可用，S09 权限和持久记录通过。

**执行：**

1. 统一成功、无结果、不可访问、超时、权限拒绝、内容不支持的返回结构；失败必须是失败，不能返回看起来正常的空证据。
2. 阅读前检查 candidate 属于当前 run 的授权来源；不接受任意路径、任意未登记 URL。
3. 验证域名解析和每次重定向目标，拒绝私网、环回、链路本地及云元数据地址；做对应边界夹具。
4. 网页和文件内的“忽略指令”等内容只作资料，不触发工具越权。
5. 401/403、不支持内容不盲重试；付费调用超时计费未知记 billing_unknown，并保守预留，不能无限补发。

**产出位置：** `R/src/evidence_agent/tools/`、`R/configs/schemas/`、`R/tests/{contract,boundary}/`、`L/probes/`。

**通过与下一步：** 成功、错误和权限边界均有验证，失败无法绕过状态校验；进入 S16。

**不通过与去向：** 权限或网络地址绕过是硬阻断，修 S09/S15 后再采轨迹；暂时外部不可用按 S14 降级，不能允许控制器直接绕开工具访问资源。

### S16｜实现可追溯证据台账与冲突表达

**依据与细节重述：** 原说明第 11、12 节。证据记录必须有 evidence_id、source_version_id、来源、哈希、版本／抓取时间、页码／标题／行号、原文区间、摘录、上下文、需求项和读取动作 ID。

**前置：** S11 位置正确，S15 工具可靠。

**执行：**

1. 只把成功读取的正文登记为证据；保存原文锚点与周围上下文，引用指向不可变版本。
2. 建 claim—evidence 关系；多文档联合结论支持对象是完整证据集合，不要求其中每一篇单独证明整个结论。
3. 对版本、时间、地域、否定和条件分别记录。两个版本说法不同不自动判矛盾；同条件不能消解才列冲突。
4. 通过 evidence_id 打开原文，自动核对摘录等于区间、页码合法、来源属于授权范围、哈希相同。
5. 更新文档、索引切换、截短上下文后再回读旧 evidence_id，验证台账不依赖当前模型上下文保存原文。

**产出位置：** `R/src/evidence_agent/evidence/`、`R/docs/architecture/evidence_protocol.md`、`D/app/`、`L/inference/`。

**通过与下一步：** 固定夹具每个引用可逐字还原，不同条件保留范围，同条件冲突不被武断消解；进入 S17。

**不通过与去向：** 原文位置错回 S11；来源授权错回 S09/S15；关系或版本错修 S16。台账不可靠时禁止大规模轨迹生成，因为错误会扩散到标签和评测。

### S17｜完成固定 Writer、Verifier 和静态 B0

**依据与细节重述：** 原说明第 12、18、19.1 节、附录 C。Writer 用无决策适配器的同一 Qwen 基座；最多6条证据、每条摘录≤512 Qwen Token；Writer和Verifier输出各≤768 Token；Verifier 是模型判断，不是人工真值。

**前置：** S13 检索、S16 台账通过。

**执行：**

1. 将控制器之外的需求提取、证据选择、Writer和Verifier固定成公共流程。需求只能由问题和用户明确约束产生，不能从评测 gold 偷取；若额外用模型处理，计入所有系统成本。
2. B0 固定混合检索后读取 Top-6 原文，再调用共同 Writer/Verifier；内部自动读取也按统一逻辑调用计账，不因没有控制器动作而免费。
3. Writer 输出结构化 claims、范围、引用和 unresolved，模板渲染答案；不使用未提供的参数记忆补成事实。
4. 先做引用完整性校验，再做模型支持性核验；核验失败将相关内容降为 uncertain 或未解决，不无限重写。
5. 验证 answered、partial、insufficient_evidence、conflicting_evidence、cancelled、timeout、failed 的语义。无依据问题返回不足，不能把“未找到”解释为“不存在”。

**产出位置：** `R/src/evidence_agent/agent/`、`R/baselines/static_rag.py`、`R/configs/prompts/`、`L/probes/`。

**通过与下一步：** B0 从资料到答案可运行，关键结论可回原文，base 路由明确；进入 S18。

**不通过与去向：** 引用错回 S16；答案丢条件修固定提示和结果协议；模型常给记忆答案则增加无答案夹具。B0 不通先修，不直接用 Agent 复杂性掩盖基础问题。

## 5. 受控循环、预算、恢复与产品门槛

### S18｜固定可见状态与确定性打包器

**依据与细节重述：** 原说明第 10.1、11.2 节、附录 A/C。控制器只看问题、需求项、快照 ID、候选、证据卡、缺口建议、近期动作、预算、来源失败；原始历史留服务端；gold_answer/gold_support 永不进入策略输入、索引或工具。

**前置：** S16/S17 通过。

**执行：**

1. 固定状态字段和 state_hash，区分真实观察、模型建议和离线标签；open_gaps 是建议，不能作正确性真值。
2. prompt≤2880 Qwen Token，completion≤192，总训练长度≤3072；先保系统协议、问题、预算、需求，再放证据、候选和旧动作。
3. 超长减少卡片数量，保留可重新读取 ID；记录 truncated=true，不在字符串中途截坏 JSON，不靠摘要保存精确数字和版本。
4. 原问题本身超长且无法完整保留必要约束时，在入口明确拒绝或要求缩小范围，不默默截去否定条件；边界写入验收表。
5. 同一输入应得到同一打包结果；保存已打包 prompt，便于训练、推理、偏好 reference 使用一致模板。

**产出位置：** `R/src/evidence_agent/agent/`、`R/configs/schemas/`、`R/docs/architecture/state_action_protocol.md`、`L/probes/`。

**通过与下一步：** 长度、关键字段、gold隔离和确定性检查均通过；进入 S19。

**不通过与去向：** 泄漏是硬阻断；定位来源并清理所有受影响衍生轨迹。打包丢关键条件回 S18 重做，不能只把模型上下文扩大而保持训练不一致。

### S19｜实现五类动作与 LangGraph 受控循环

**依据与细节重述：** 原说明第 10 节、附录 B/C。动作固定为 local_search、web_search、read_evidence、finish、abstain；动作四字段全部存在，不适用为null，禁止额外字段；query≤256字符、candidate_id≤128字符。

**前置：** S15 工具、S18 状态、S17答案链路通过。

**执行：**

1. 动作只输出短 JSON，不生成任意工具名、路径或长篇思维链；结束 reason_code 固定为证据充分、缺来源、冲突、低收益、预算耗尽、工具不可用六类枚举。
2. 建 load→policy→dispatch→update 的循环；finish/abstain 进入固定 write→verify→finalize，硬预算不足时由执行器决定安全出口。
3. dispatch 校验Schema、参数含义、联网权限、candidate存在和预算，不能相信结构化解码已经保证动作合理。
4. 首次非法输出最多一次短修复并计资源；再次失败保留 failed_policy 原因并以对外失败协议结束。
5. 连续重复同一规范化query且版本不变时读缓存、计逻辑工具调用；连续两次无新增证据只标状态，不自动判问题无解。

**产出位置：** `R/src/evidence_agent/agent/`、`R/configs/schemas/`、`L/inference/`、`R/tests/contract/`。

**通过与下一步：** 五动作均可走通，未知动作与候选被拒，循环出口可追踪；进入 S20。此时 E0 仅完成基本执行图，尚待预算和恢复验收。

**不通过与去向：** 死循环、非法ID、结束状态错留在 S19；工具问题回 S15，状态问题回 S18。不能靠 LangGraph 递归限制代替预算设计。

### S20｜落实硬预算、模型预留和费用账本

**依据与细节重述：** 原说明第 13、22 节和附录 A。工具8次、live搜索≤3；累计输入48000、输出4096 Token；Writer/Verifier预留1536输出Token；单上下文8192；任务240秒，单模型60秒且不得超过剩余时间。

**前置：** S19 基础图可运行，S09 使用事件存储通过。

**执行：**

1. 每次请求前检查该次最大开销、结尾预留、剩余时间；输入也要计入实际序列和累计上限，不只是输出。
2. finish/abstain 不算外部工具调用，但对应策略、Writer、Verifier都计模型成本。候选需求提取、重试、修复、失败、B2内部协调也全部计入。
3. 逻辑工具数、物理请求数、缓存命中、API credits分开。重复读取或查询不能靠缓存从逻辑预算中消失。

1. 按task_id切分并沿用来源隔离；对状态、任务、原文哈希和近重复跨集检查，不能把同轨迹不同state拆到两边。
2. JSONL记录task_id、state_id、split、prompt、completion、state_hash、source_manifest_hash；格式全表一致，同一tokenizer模板渲染。
3. 逐Token核验正常、最长、中文、含工具错误四种样本：prompt标签为-100，动作JSON为有效学习目标，EOS、padding、模板边界正确。
4. 报告各动作数量和比例，超过一半时生成对应缺失场景补充采集，不改正确动作标签，也不重复抽样冒充独立状态。
5. 对gold泄漏执行T25：不仅查字段名，还查误入索引、工具、缓存和提示的答案内容；发现污染撤销衍生数据并回溯来源。
6. 冻结数据manifest、哈希与实际规模。达到最低但未达到4000/800时明确“低于目标规模”；dev800原方案没有另设最低数，实际开发状态数和局限必须保留，端到端dev160题仍按原目标执行。

**产出位置：** `D/sft/<dataset_id>/`、`L/audits/`、`D/manifests/`、`R/training/data/`。

**通过与下一步：** train≥2000独立合格状态，划分、动作比例、掩码与格式全部通过；进入S31。达到4000/800才可标“目标数据规模完成”。

**不通过与去向：** 低于2000不做正式训练；回S29补场景或修过滤。掩码错误修S30，不把prompt也学进去凑损失下降。泄漏回S25—S29定位，并使受影响数据、检查点失效。

## 7. SFT 训练、导出与阶段判断

### S31｜完成32条样本训练探针与显存处理

**依据与细节重述：** 原说明第16.1—16.3节。QLoRA4-bit NF4＋double quantization、BF16；LoRA r16/alpha32/dropout0.05，目标q/k/v/o和gate/up/down投影，bias none；基座冻结，microbatch1，checkpointing开启，use_cache=false，packing=false。

**前置：** S30通过，停Worker/vLLM并核对GPU独占，S07保存重载探针仍适用。

**执行：**

1. 使用32条真实格式样本短训练，记录显存峰值、可训练参数、梯度、有限loss、保存与重载。
2. 对照同一组未训练动作输出验证链路；只作为探针，不将小样本提升当正式成果。
3. 初始长度3072（prompt2880＋completion192）。OOM先清其他GPU进程，保持microbatch1和checkpointing。
4. 仍OOM才按原规则改总长2048、线上prompt1856；这是全链配置变更，重新打包数据、检查掩码、重跑可比基线，并更新manifest。
5. 长度降级后仍OOM则硬件／环境门槛失败，停长任务，不丢completion、不悄悄缩问题、不自动上多卡。

**产出位置：** `L/training/<experiment_id>/`、`A/checkpoints/<experiment_id>/`、`L/probes/`、必要的配置变更日志。

**通过与下一步：** 前后向、参数冻结、显存、保存重载正确，所有降级影响已同步；进入S32。

**不通过与去向：** 掩码回S30，环境回S06/S07；降级改了可见状态就回S18/S28—S30重新冻结相应部分。不得带着未确认的数值异常直接做正式训练。

### S32｜运行正式 SFT 并保存完整训练证据

**依据与细节重述：** 原说明第16节及附录A。有效batch16（micro1、累积16）、2epoch、lr1e-4、cosine、warmup0.05、weight_decay0.01、max_grad_norm1、paged_adamw_8bit、seed42；每10更新步日志、每100保存/验证并保存最后一步，检查点最多2个，最佳适配器独立保留。

**前置：** S31通过，正式数据、环境、配置哈希已冻结，费用预测仍满足。

**执行：**

1. manifest绑定基座revision、数据哈希、tokenizer、模板、代码、参数、随机种子与训练阶段ID。
2. 确认completion_only_loss=true，再启动正式训练，区分microstep与optimizer update；4000样本、batch16、2epoch预期500次更新。
3. 实际样本数不同按实际批次数和尾批规则记录更新数，不能照搬500；训练中断恢复使用同数据、同优化器与有效检查点，不冒充从头独立实验。
4. 监控NaN/Inf和异常梯度；出现时立即停止查数据和梯度。仅允许按原规则降lr至5e-5重跑一次；再次失败回数据／环境修复。
5. 保留训练日志、保存事件和适配器哈希，清理可重建临时检查点前先确认最佳适配器已有独立副本。

**产出位置：** `L/training/<experiment_id>/`、`A/checkpoints/<experiment_id>/`、`A/adapters/sft/<experiment_id>/`、`L/billing/`。

**通过与下一步：** 正式训练按配置结束、数值有限、适配器可保存且记录完整；进入S33。loss下降仅证明优化发生，不证明应用变好。

**不通过与去向：** 按已记录的数值或资源分支处理；数据不足不称正式完整训练；预算触发停止保留有效检查点。未经有效SFT适配器不能进入DPO。

### S33｜实际 vLLM 导出、路由检查与开发集筛选

**依据与细节重述：** 原说明第16.4、18.1、19.6节。QLoRA训练与BF16推理数值路径不同；检查点先看状态级合法率、停止分布，再跑预先固定40道开发任务；最终选型用160道开发任务。

**前置：** S32有效适配器，训练进程退出且显存释放。

**执行：**

1. 将候选适配器加载到固定vLLM，rank上限16；policy请求指定adapter，Writer和Verifier明确走base。执行T24路由检查。
2. 保存同一批动作探针在训练量化路径与vLLM路径的输出差异；业务合法、预算和权限必须都正常。
3. 在独立开发状态集统计JSON有效率、动作混淆、参数合法率、停止动作准确性；不把这些当端到端质量。
4. 每个预登记候选在同一40道开发任务运行，与E0在同40题比较Q/G/成本，选检查点；选择方法和候选清单先登记，不能看分数后增加有利检查点。
5. 对选出的E1跑完整160开发任务，与同集E0确认质量、支持、错误确定作答和动作合法率；将此记录用于S40，避免不同子集直接比较。

**产出位置：** `A/adapters/sft/`、`L/evaluation/<evaluation_id>/`、`R/docs/models/sft_model_card.md`、`R/docs/evaluation/release_selection.md`。

**通过与下一步：** 有运行正常、可追溯的E1候选及完整开发结果；进入S34。效果是否合格单独记录，不以训练loss代替。

**不通过与去向：** vLLM导出或路由错回S07/S33；状态不合法查S30/S32；效果下降保留真实结果，不针对测试调参。可以回已登记的数据修复流程，但新实验必须新ID并重走开发验收。

### S34｜结清 SFT 阶段状态并决定 DPO 是否可开始

**依据与细节重述：** 原说明第17、19.6、20节。本项目应完成SFT和DPO实验，但并不保证训练版适合发布；正式DPO必须有稳定SFT参考。

**前置：** S32/S33已给出真实训练、导出和开发结果。

**执行：**

1. 分别判定数据目标、训练流程、适配器可调用、效果门槛四项，不能只写“成功／失败”。
2. 若SFT可运行且满足发布门槛，登记E1候选；尚不在最终测试上验证，不提前公开声称提升。
3. 若可运行但效果门槛不过，E0仍是产品回退；允许继续DPO研究，但参考和分支策略必须是已固定同一SFT，不把它称已发布版本。
4. 若SFT没完成、数值损坏、S33业务合法性探针未通过或权限预算可绕过，阻断DPO，先回S30—S33修复。开发集合法率是否达到0.98仍单独按发布门槛判断，不能与适配器是否可运行混为一谈。
5. 根据S35—S39的双分支、复核、reference和评测开销更新预算，不能只为DPO训练本身留显卡小时。

**产出位置：** `L/steps/S34/`、`R/docs/models/sft_model_card.md`、`L/billing/forecast.json`、`R/docs/plan/progress.md`。

**通过与下一步：** 参考SFT可用、研究条件与预算充分时进入S35。

**不通过与去向：** 流程失败回S30—S33；预算不足STOPPED，保留E0/E1与未完成清单。不能用基座代替SFT却仍称“原定SFT后DPO”，也不能因DPO阻塞就删掉这项要求。

## 8. 同状态偏好与 DPO 实验

### S35｜固定同状态双分支采集环境

**依据与细节重述：** 原说明第17.1—17.2节。DPO学习“同一个可见状态下哪个下一步更好”；不能配两个问题、不同历史或不同预算的动作。后续结果用于标注，completion只保留最开始动作JSON。

**前置：** S34允许继续，固定SFT检查点、工具、来源与Writer/Verifier。

**执行：**

1. 仅从train/dev任务的SFT运行中收集未结束状态；按task_id隔离，不读取测试任务。
2. 每个state采两个不同且合法动作，优先继续搜索对停止、网页对本地、阅读对重复搜索；不人为把非法动作作为廉价rejected。
3. 克隆同一可见状态及服务端语义状态：资料快照、已读证据、历史、剩余逻辑预算和可用候选一致；分支物理run_id不同但不能影响策略输入。
4. 分别执行第一个动作，之后均用冻结同一SFT继续到结束；共同Writer、Verifier不变，缓存口径一致。
5. **执行补充：** 离线候选采样温度0.6，后续策略采样温度0.3，以seed42执行、seed43复核；Writer/Verifier仍温度0。两分支和两次复核按同一设置运行，离线采集设置独立记录，不修改线上温度0。
6. 只有服务实际支持seed时记录其生效情况；不支持或不能保证确定性时保留原始输出和限制。预算不足或状态无法克隆时放弃该对，不拼接另一状态。

**产出位置：** `R/training/preferences/`、`R/docs/data/preference_protocol.md`、`L/branches/<collection_id>/`。

**通过与下一步：** 同状态哈希、来源、预算、历史可核对，两个动作不同且合法，分支均有完整结果；进入S36。

**不通过与去向：** 克隆差异回S18/S21/S35修；工具变化回S15。一个分支看了gold或额外来源时整对丢弃并查污染范围，不能用高分分支保留偏好。

### S36｜按结果筛选偏好并完成第二 seed 复核

**依据与细节重述：** 原说明第17.3节。目标train600对、dev100对；最低train300对。Q为预登记任务质量，G为引用支持，C为剩余执行资源代理；不只问教师偏好哪动作。

**前置：** S35分支可审计，S28评分器已验证。

**执行：**

1. 为每个分支计算Q、G和从该状态起的后续成本。C=输入Token/48000＋输出Token/4096＋工具次数/分支初始工具预算；只用于训练标签，不等于人民币。
2. 质量规则：一方Q至少高0.10且G不比另一方低超过0.02，选择该方。
3. 否则仅当Q差≤0.02、G差≤0.02且C至少低15%时选较便宜方；两个都错、差别不够、权衡不明确则丢弃。
4. **执行补充：** 成本相对改善以较高成本方为基准；其成本为0时不触发便宜规则；初始工具预算为0的状态不做本成本偏好。G不可比时不能把缺失值当满分，该候选不构造正式偏好对；无答案伪造错误仍保留为分析案例，不能反向选伪造方。
5. 用第二seed复核入选对：两次判定同一chosen才保留，反转或变成近似平局丢弃。证据不足题伪造确定答案不能因省调用获选。
6. 每对保存state、两个动作、两个后续执行ID、Q/G/C、label_reason和复核结果。chosen/rejected不包含后续工具观察或最终答案。
7. 统计动作覆盖和丢弃原因，累计到600/100或预算停止。仅700个最终合格对在双分支双seed下就涉及2800次后续执行，另有被筛掉的候选开销，必须纳入预算预测。

**产出位置：** `L/branches/`、`L/audits/`、`D/dpo/<dataset_id>/`、`L/billing/forecast.json`。

**通过与下一步：** train≥300独立合格对，dev实际规模透明，同状态、评分和复核无未解决问题；进入S37。达到600/100才标目标偏好规模完成。

**不通过与去向：** 低于300不正式DPO；回S35补有分歧场景或修评分，不能复制对。预算耗尽停止并保留E0/E1，不将“短探针”计为原定合格规模DPO实验。

### S37｜验证 SFT reference、缓存和 DPO 短探针

**依据与细节重述：** 原说明第17.4、23节T23。reference必须是冻结同一SFT策略，不能关闭LoRA后误用基座；同一量化基座分别加载train与reference适配器，预计算reference log-prob降低显存。[W07]

**前置：** S36数据达到最低规模，S34固定SFT哈希有效；停推理、训练GPU独占。

**执行：**

1. 明确train和reference适配器名称及来源；reference冻结，train初始化与其一致。名称与trainer配置一一对应，不只凭名字认为它正确。
2. 缓存键包含SFT检查点、tokenizer、chat template、样本和掩码哈希；配置任一改变即失效。
3. 抽正常、最长、中文偏好对，比较缓存与单独冻结SFT计算结果，记录预先约定的数值容差和实际差异。
4. 关闭reference适配器执行T23故障注入，确认检查能发现误用base；不能只测试正常路径。
5. 用少量真实对做DPO前后向、保存重载、梯度与显存探针，确认仅训练目标适配器发生变化，reference和base未变。

**产出位置：** `D/dpo/<dataset_id>/reference_cache/`、`L/probes/`、`L/training/`、`R/training/dpo/`。

**通过与下一步：** 缓存等于正确SFT参考、故障注入被阻断，训练路径和显存通过；进入S38。

**不通过与去向：** reference错误立即阻断，修配置并全部重算缓存；样本模板变化回S30/S36重渲染；OOM先清服务和核对预计算策略。若必须改变长度，按S31全链变更，不暗改DPO数据边界。

### S38｜运行正式 DPO 并记录训练与异常

**依据与细节重述：** 原说明第17.4—17.5节。从固定SFT初始化；LoRA继承；beta0.1、sigmoid、lr5e-6、2epoch、micro1、累积8；长度prompt≤2880、chosen/rejected≤192、总≤3072；seed42，10步日志、50步保存，最后一步另存，最多2检查点。

**前置：** S37通过，费用预留足够，数据和reference缓存冻结。

**执行：**

1. 保存完整manifest，明确实验是在“动作偏好”上训练，不是把整段工具轨迹作为completion。
2. 记录偏好间隔、chosen/rejected log-prob、loss、梯度和保存事件；检查reference哈希在训练前后不变。
3. 600对、有效batch8、2epoch为150次optimizer update；数量不同时按实际尾批规则记录。
4. 数值异常立即停，回查坏对、掩码、reference和环境；原方案没有DPO数值异常的自动降学习率规则，不能照搬SFT例外或临时换目标函数。
5. 需要参数补丁时先记录原因与影响、重新探针和开发评测；它是新实验，不能覆盖原固定参数结果。

**产出位置：** `L/training/<experiment_id>/`、`A/checkpoints/<experiment_id>/`、`A/adapters/dpo/<experiment_id>/`、`L/billing/`。

**通过与下一步：** 合格规模训练完成、数值有限、适配器与参考可核对；进入S39。

**不通过与去向：** 参考问题回S37，偏好问题回S35/S36，环境问题回S06/S07。修复后更换experiment_id，保留旧记录；不能以训练loss下降提前宣称DPO提升。

### S39｜导出 E2 并完成同条件开发评估

**依据与细节重述：** 原说明第17.5、18、19.6节。E2=E0＋SFT后DPO策略，公共Writer/Verifier不变；最终测试不参与选检查点。

**前置：** S38有效适配器，vLLM恢复推理。

**执行：**

1. 核对DPO导出仍包含正确的SFT后续参数，而非只导出一个无法复现的差分；保存base、初始化SFT与最终adapter关系。
2. 重新做动作Schema、candidate参数、base/adapter路由、预算和权限探针，检查停止分布是否异常塌缩。
3. **执行补充：** DPO候选同样先按S33固定40开发题筛选，再对选出E2运行160完整开发题；候选规则预登记，不针对测试反复挑选。
4. 报告端到端Q/G、证据不足错误确定作答、合法率、Token和调用成本，并保留状态级偏好指标，两者不互相替代。
5. 完善DPO模型卡：偏好来源、规模、reference、训练、部署差异和负结果；若不合格仍保留适配器与原因。

**产出位置：** `A/adapters/dpo/`、`L/evaluation/`、`R/docs/models/dpo_model_card.md`、`R/docs/evaluation/release_selection.md`。

**通过与下一步：** E2真实可运行、有完整开发结果且条件与E0/E1一致；进入S40，不要求它一定优于E1。

**不通过与去向：** 导出或路由错回S37—S39；效果不合格按S40回退，不删负结果。若DPO未完成，S40将其标不可用候选，完整训练目标仍为未完成。

## 9. 发布选择、冻结与正式评测

### S40｜只在开发集执行唯一发布选择

**依据与细节重述：** 原说明第19.6节、附录A。160开发题，Q为英文平均F1与中文平均rubric各一半；G为有定义任务的宏平均引用支持率；另看中文证据不足类。E0始终回退。

**前置：** E0完整开发结果，E1/E2各自可用状态和同条件结果明确。

**执行：**

1. 同样的160题、同快照、同Writer/Verifier、同预算计算E0/E1/E2；训练失败的版本不伪造结果。

5. 保存实际指标、差值、每条门槛判断和最终选择；高成本但高质量也按既定规则处理，不能临时加一个偏好权重。

**产出位置：** `R/docs/evaluation/release_selection.md`、`L/evaluation/`、`D/manifests/`、`R/artifacts/artifact_index.json`。

**通过与下一步：** 发布策略和哈希唯一，选择只基于dev；进入S41。DPO不入选仍可视为实验完成，前提是训练、数据和开发证据齐全。

### A.4 HTTP API 与结果语义速查

以下是需要落实的产品契约，保留接口边界而不展开代码实现。除最小健康检查外，按后端Token规则鉴权；请求中的项目权限也必须检查。

| 方法与路径 | 输入／目的 | 必须返回或保障 |
| --- | --- | --- |
| GET /healthz | 进程是否存活 | 最小状态，不泄露配置与密钥 |
| GET /readyz | 服务是否能接受研究任务 | 模型、索引、Worker就绪情况 |
| POST /v1/projects | name、description | project_id |
| POST /v1/projects/{id}/documents | 文件上传 | document_id、version_id、ingest_job_id |
| GET /v1/documents/{id} | 查解析、索引、版本 | 明确处理中、成功、失败状态 |
| POST /v1/runs | project_id、question、allow_web、budget_profile | run_id、queued，异步返回 |
| GET /v1/runs/{id} | 查运行与结果 | 状态、预算、错误、完成结果 |
| GET /v1/runs/{id}/events | SSE，Last-Event-ID重连 | 原任务事件，不另建run |
| POST /v1/runs/{id}/cancel | 申请取消 | 取消确认，后续停止派发 |
| GET /v1/runs/{id}/evidence/{evidence_id} | 打开引用 | 原文、位置、来源、固定快照 |
| GET /v1/runs/{id}/export | 下载结果 | 答案、引用与轨迹摘要包 |

普通用户budget_profile固定standard；b4/b8/b12仅内部评测，不允许外部提交无限预算。Idempotency-Key绑定请求体，不接受同key不同体。

| 结果状态 | 正确含义 |
| --- | --- |
| answered | 主要需求已回答，关键结论通过本系统核验；不等于外部事实绝对正确 |
| partial | 有支持的局部回答，仍有未解决需求 |
| insufficient_evidence | 当前允许资料与已执行搜索不足以支持主要结论 |
| conflicting_evidence | 同条件冲突无法消解；不同版本的不同结论不必自动归此类 |
| cancelled | 用户取消，停止派新调用，已有费用和已完成步骤保留 |
| timeout | 时间耗尽，保留已获得的中间结果 |
| failed | 模型、工具、存储或策略等错误致流程无法正常结束，具体原因另记 |

claim至少保留文本、对应需求项、evidence_ids、适用范围和核验状态；结果还要有unresolved、证据位置和usage。核验状态supported/unsupported/conflicting/uncertain属于模型判断，与gold真值、任务终态分开。

## 附录 D. 产物交接、失效传播与完成等级

### D.1 何种变更会让后续结果失效

| 发生变更 | 必须重新检查／构建 | 不能继续沿用什么 |
| --- | --- | --- |
| 原文或解析位置变化 | S11—S16、相应索引与gold映射 | 原证据位置与旧来源哈希 |
| 分块、embedding或检索变化 | S12—S15、S22、S28 | 声称同工具条件的旧对比 |
| 控制器状态长度／模板变化 | S18、S28—S31、相应轨迹 | 旧状态样本和不匹配掩码 |
| 题目gold或split更正 | S24—S30及受影响评分 | 污染样本与未标版本旧统计 |
| Writer/Verifier或需求提取变化 | S17、S22、S28及受影响评测 | 隔离决策优化影响的原比较 |
| SFT reference改变 | S35—S38重新采集/评估适用性并重算缓存 | 旧reference log-prob与旧初始化关系 |
| vLLM/adapter导出变化 | S07、S33/S39、路由及开发检查 | 仅训练端量化推理的可用性结论 |
| 测试后修严重可靠性问题 | 新代码和冻结版本，S41后相应重测 | 原测试仍完全独立未见的表述 |

旧结果可以作为历史保留；失效指不能再拿来证明新版本在同一条件下的结论，不是要求删除原始记录。
