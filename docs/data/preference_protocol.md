# 同状态偏好协议（S35—S36）

> 状态：PROTOCOL_DRAFT（2026-10-27）  
> 依据：原说明 §17.1—17.3；执行方案 S35—S36。正式采集前不得在本文件外另定规则。

## 1. 目的

学习「同一可见状态下哪一个下一步动作更好」。completion 只保留分支起点动作 JSON；后续执行结果只用于标注，不进入 prompt / 训练目标。

## 2. 状态来源

- 仅 train/dev 任务的 SFT 运行未结束状态；按 `task_id` 隔离。
- 禁止读取 test 任务或任何 gold 字段进入策略输入。
- 状态哈希覆盖：资料快照集合、已读证据、历史动作摘要、剩余逻辑预算、可用候选。

## 3. 双分支采集（S35）

1. 每个 state 采两个**不同且合法**动作；优先：继续搜索 vs 停止、网页 vs 本地、阅读 vs 重复搜索。
2. 不人为注入非法动作作为廉价 rejected。
3. 克隆同一可见状态与服务端语义状态后分别执行第一个动作；此后均用冻结同一 SFT（`e1` 候选）继续到结束。
4. Writer/Verifier 不变、温度 0；离线候选采样温度 0.6，后续策略 0.3；seed42 执行、seed43 复核。
5. 仅当服务实际支持 seed 时记录生效；不支持则保留原始输出与限制说明。
6. 预算不足或无法克隆则放弃该对，不跨状态拼接。

## 4. 标签规则（S36）

对每个分支计算 Q、G、C：

- `C = input_tokens/48000 + output_tokens/4096 + tool_calls/branch_initial_tool_budget`
- 质量：一方 Q 至少高 0.10 且 G 不低于另一方超过 0.02 → 选该方。
- 否则仅当 `|ΔQ|≤0.02`、`|ΔG|≤0.02` 且 C 相对较高成本方至少低 15% → 选便宜方；较高成本为 0 时不触发便宜规则；初始工具预算为 0 不做成本偏好。
- G 不可比（缺失）时不构造正式偏好对；两边都错、差别不够则丢弃。
- 证据不足题伪造确定答案不得因少调用获选。
- seed43 复核：两次判定同一 chosen 才保留；反转或近似平局丢弃。

- 偏好集：`D/dpo/<dataset_id>/`（train/dev jsonl、quality_report、manifest）
- 最低正式 DPO：train ≥ 300 独立合格对；目标 600/100。
